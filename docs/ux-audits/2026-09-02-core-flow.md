# Olive core-flow UI audit

Audit date: September 2, 2026  
Surface: current local web build, reviewed in the Codex in-app browser  
Flow: open Olive, start a contraction, stop and review it, inspect correction controls, open urgent help, open partner sharing, and reveal secondary tools

## Overall verdict

The primary timing interaction is calm, distinctive, and close to delightful. The active-timer and sharing states are especially clear. The experience loses that clarity immediately below the primary task: a completed contraction exposes a dense annotation form, the first-use coach competes with the main action, and several unlabeled header icons depend on recognition. Olive is helpful and internally coherent, but the complete surface does not yet feel as effortless as the timer itself.

## Captured flow

1. **Fresh timing screen — healthy with moderate first-use friction.** The large warm Start surface dominates correctly, urgent help stays visible, and manual entry is easy to find. The inline three-step coach, Share card, More tools card, secondary empty-state prompt, and header icons create more simultaneous instruction than a person in labor should have to parse.
2. **Active contraction — excellent.** The view collapses to elapsed time, start time, wake-state feedback, floating-timer access, and one unmistakable Stop action. This is the strongest screen in the product.
3. **Completed contraction summary — healthy.** The return to Start is immediate, a visible saved confirmation offers Undo, and the factual “first one recorded” copy avoids diagnosis. Clear/delete/read actions are comparatively small and visually quiet.
4. **History and correction details — needs simplification.** Every record exposes ten intensity choices, four late-stop corrections, six symptom tags, front/back body controls, pain regions, notes, Save, and Discard. These are useful capabilities but create a clinical-looking wall of controls and make the ordinary task of checking a timestamp feel heavy.
5. **Partner sharing — excellent.** “Summary only — recommended” is selected by default, the difference from the full timeline is explained plainly, the bearer-link warning is adjacent, Advanced stays collapsed, and there is one clear creation action.
6. **Urgent-help disclosure — healthy.** The boundary is visible without blocking timing, avoids relying on a timing pattern, names several urgent situations, and provides a direct path to add the care-team number. The paragraph is necessarily dense and still needs professional/native-device review.
7. **Secondary tools — structurally sound but broad.** Hiding preparation and record-keeping behind More tools protects the timer. Once expanded, Hospital bag, Exams, People, Labor events, Sessions, and Backup are understandable, but the collection spans preparation, labor, records, and recovery without further grouping.

## Highest-impact improvements

1. Collapse each history record to time, duration, intensity summary, notes indicator, and an **Add details** action. Reveal symptoms, pain map, and correction tools only on demand.
2. Replace the first-use carousel card with one short sentence plus a dismissible **How Olive works** disclosure. The main Start control already teaches the essential action.
3. Give Share, sound, theme/settings, and voice persistent visible labels on first use or combine secondary header actions under one clearly named menu. Icons alone are not reliably self-explanatory under stress.
4. Group More tools into plain-language sections such as **Prepare**, **During labor**, and **Records & recovery**, while keeping the timer above all of them.
5. Preserve the active-timer and sharing layouts. They are the clearest expression of Olive's intended calm, private product character.

## Accessibility and evidence limits

The captured accessibility tree exposed meaningful button names, expanded/collapsed state, focus movement, radio descriptions, and separate sharing choices. Screenshots alone cannot verify VoiceOver/TalkBack reading order, physical touch ergonomics, system text scaling, color contrast values, interruption recovery, or performance on native WebViews. Those remain signed-device gates.

Screenshots were captured and inspected inline during this audit. The available in-app browser surface did not expose a supported local screenshot-export path, so this file retains the audit notes rather than duplicate image files.
