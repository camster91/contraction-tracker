# Olive v1.2 — Birth Journey specification

Status: product direction approved; implementation not started.

## Release objective

Extend Olive from a focused contraction timer into a private birth-journey
companion covering approximately 36 weeks of pregnancy through 12 weeks
postpartum. v1.2 establishes the shared journey foundation without adding
accounts, diagnostic logic, mandatory cloud storage, or a generic chatbot.

## Users and permissions

### Record owner

- Creates, views, edits, completes, archives, exports, and deletes all journey
  information.
- Chooses which categories are included in a partner share or care-team handoff.
- Changes the journey phase manually.

### Partner or support person

- Opens an expiring invitation without creating an account.
- Sees the responsibilities and information explicitly shared with that invite.
- Can mark an assigned responsibility complete and post a short update when the
  invite permits contribution.
- Cannot see private notes, unshared questions, or care-team contact details by
  default.

### Care professional

- Receives a user-reviewed text or PDF handoff.
- Does not require an Olive account and does not edit the local record in v1.2.

## Feature 1: unified care card

The care card assembles information Olive already stores and adds a small set of
journey-level fields.

### Fields

- Preferred name and optional pronouns
- Estimated due date and manually selected journey phase
- Primary care-team name and contact action
- Birth location and address
- User-entered care instructions and timing reminder
- Allergies or important notes, explicitly labeled "entered by you"
- Emergency contact selected from existing people
- Last updated timestamp

### Actions

- View, edit, export, copy, and include in a reviewed share
- One-tap call for a saved phone number
- Hide any field from a generated handoff

### Empty and error states

- An empty card shows three optional starter fields, not a long required form.
- Invalid phone numbers remain editable but do not render a call action.
- Missing dates never infer a journey phase.
- Export and copy failures keep the card visible and offer retry.

## Feature 2: partner responsibilities

Responsibilities are practical support actions, not medical tasks.

### Examples

- Bring the hospital bag
- Contact the chosen family member
- Feed the pet
- Install the car seat
- Keep water nearby

### Actions

- Create, edit, reorder, assign, complete, reopen, and delete
- Assign to an existing person or leave unassigned
- Mark private or include in a specific partner invitation
- Add an optional due time or phase, not a recurring clinical schedule

### States and conflicts

- Empty: show suggested practical tasks that are added only after selection.
- Offline: changes persist locally and queue for an active shared session.
- Concurrent completion: completion is idempotent; the earliest completion time
  is retained and the UI reconciles when connectivity returns.
- Revoked invite: partner mutations stop immediately and the owner retains the
  local responsibility history.

## Feature 3: provider questions

Questions help the parent remember what they want to ask; Olive does not answer
them.

### Fields and actions

- Question text
- Optional category: birth, recovery, feeding, medication, mood, or other
- Optional appointment/date
- Private by default
- Pin, reorder, mark asked, record the user's own notes, reopen, and delete
- Select questions for a clipboard or PDF appointment summary

### Safety rules

- No automated medical answer is displayed.
- Urgent-sounding words do not trigger a diagnosis. A persistent, neutral note
  reminds users to contact their professional or emergency services when they
  believe help is urgent.
- User notes are labeled as notes, never provider instructions, unless the user
  explicitly marks them as instructions received from a named provider.

## Feature 4: first-12-weeks timeline

The postpartum timeline records logistics and personal notes without grading
recovery.

### Entries

- Appointment or call
- Recovery note
- Support visit or meal
- Question reminder
- Personal milestone

### Actions

- Create, view, edit, complete, archive, and delete
- Filter by upcoming, completed, or private
- Export a selected date range
- Add a local device reminder when the native platform supports it and the user
  explicitly grants permission

### Boundaries

- No symptom severity score, treatment suggestion, feeding target, sleep target,
  medication dosage, or newborn-development judgment.
- No statement that a completed appointment means recovery is complete.
- Postpartum begins only when the owner changes the phase or confirms the
  existing Baby is here flow.

## Data model

Create `src/lib/journey.ts` with versioned, normalized types:

```ts
type JourneyPhase = 'preparing' | 'labor' | 'postpartum' | 'archived';

interface JourneyProfile {

  pronouns?: string;
  estimatedDueDate?: string;

  birthLocation?: string;
  birthAddress?: string;
  importantNotes?: string;
```

### Persistence

- Store the versioned journey document under `olive:journey:v1`.
- Mirror it to IndexedDB using the existing recovery pattern.
- Extend JSON backup/export with a schema migration that leaves v1.1 backups
  valid and initializes missing journey collections as empty.
- Validate lengths, dates, enum values, IDs, and cross-record references on
  import. Reject or omit invalid fields without overwriting healthy local data.
- Do not upload the journey document automatically.

## Sharing and relay contract

v1.2 should extend the existing capability model, not create accounts.

- Every invite has an explicit category allow-list such as
  `responsibilities`, `status`, or `contractions`.
- Care card and provider questions are excluded by default.
- The owner sees a human-readable review screen before creating or updating an
  invite.
- Relay responses omit private fields and internal client identifiers.
- Host capability controls invite creation, permission changes, and revocation.
- Partner mutation endpoints accept only category-scoped, normalized updates.
- SSE may carry responsibility/status changes but must not place capability
  tokens in logs or general page URLs.

## Loading, interruption, and failure behavior

- Loading never blocks the contraction timer or existing local record.
- An empty journey opens to one recommended next step based on the manually
  selected phase.
- Storage quota errors preserve the last healthy copy and surface export.
- Offline edits show a local-only status until sync succeeds.
- Relay failures do not remove local content or imply that a partner received an
  update.
- Duplicate submits are idempotent.
- Deleted or revoked content disappears from subsequent viewer snapshots.
- Dates render in the device locale and time zone; exported data retains ISO
  timestamps.

## Accessibility and localization requirements

- Mobile-first at 320 CSS pixels and larger, including 200% text zoom.
- All sheets use the existing modal focus hook and restore focus on close.
- Touch targets are at least 44 by 44 CSS pixels for primary journey actions.
- Status is never conveyed by color alone.
- Labels and errors are available to assistive technology.
- New user-facing strings are introduced through a translation-ready message
  map. v1.2 ships English copy but must not add more scattered hard-coded UI
  strings.
- Layout supports longer translated text and right-to-left direction without
  horizontal page overflow.

## Delivery slices

1. **Journey foundation:** model, normalization, migration, backup, and Today
   shell behind a local feature flag.
2. **Care card and questions:** offline CRUD, reviewed summary/export, and
   accessibility coverage.
3. **Responsibilities:** local assignment flow and partner-safe permission
   contract.
4. **Postpartum timeline:** offline entries, optional local reminders, and
   archive/export.
5. **Release integration:** sharing review, relay hardening, store copy, native
   sync, production QA, and feature-flag removal.

## Release acceptance criteria

- Existing v1.1 users upgrade without losing contractions, sessions, people,
  care-plan settings, shares, checklists, exams, or backups.
- The timer remains usable during every journey loading/error state.
- All journey CRUD works offline and survives reload.
- No phase advances without explicit owner confirmation.
- No journey category reaches the relay before explicit reviewed sharing.
- A partner sees and changes only permitted categories.
- Care-team and appointment summaries contain factual user data and no
  diagnostic conclusion.
- Backup round-trip preserves all journey records and remains compatible with
  valid v1.1 backups.
- Chromium and WebKit mobile suites, accessibility checks, relay security tests,
  production build, Android release build, and post-deploy smoke tests pass.

## Deferred beyond v1.2

- Accounts and longitudinal cloud sync
- Clinician portal or electronic medical-record integration
- AI-generated clinical advice
- Medication dosing or symptom scoring
- Apple Watch, Live Activities, and HealthKit
- Multiple languages beyond the translation-ready foundation
- Paid family subscriptions
